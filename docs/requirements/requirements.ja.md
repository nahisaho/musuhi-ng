## 1. ドキュメント概要

### 1.1 目的

本要件仕様書は、MUSUHI 2.0フレームワークの包括的な機能要件および非機能要件を定義します。MUSUHI 2.0は、6つの既存SDD(Specification Driven Development)フレームワークの分析に基づき、次世代の仕様駆動開発プラットフォームとして設計されます。

### 1.2 スコープ

本仕様には以下が含まれます:

- 8つの主要機能(Constitutional Governance、Change Workflow、Multi-Agent Orchestration、Parallel Task Execution、Brownfield Gap Analysis、Interactive Dashboard、Iterative Verification、Multi-Platform AI Integration)
- 72の機能要件(EARS形式)
- 19の非機能要件
- トレーサビリティマトリクス(要件 ↔ 調査結果 ↔ テスト)
- マルチプラットフォームAIアシスタント統合(8つのプラットフォーム):
  - VS Code + GitHub Copilot
  - Cursor
  - Zed
  - Windsurf IDE
  - Claude Code
  - Codex CLI
  - Gemini CLI
  - Qwen Code

本仕様に含まれないもの:

- 詳細な実装設計(System Architectエージェントが担当)
- 特定のプログラミング言語の選択
- サードパーティツールの具体的なバージョン
- レガシーMUSUHI 1.x移行ツール
- Webダッシュボード(フェーズ5)

### 1.3 対象読者

- プロダクトマネージャー
- システムアーキテクト
- ソフトウェア開発者
- テストエンジニア
- QAチーム
- エンタープライズ意思決定者

## 5. 制約

### 5.1 技術的制約

- **AIプラットフォーム依存**: エージェントオーケストレーションは、AIプラットフォームがツール呼び出し/関数呼び出しをサポートすることを前提とする
- **ターミナルベースUI**: インタラクティブダッシュボードは、ANSI/VT100をサポートするターミナルが必要
- **ファイルシステムアクセス**: 変更ワークフローは、specs/、changes/、archive/への読み取り/書き込みアクセスが必要
- **Git統合**: トレーサビリティとバージョン管理はGitリポジトリを前提とする

### 5.2 ビジネス制約

- **オープンソースライセンス**: MUSUHI 2.0はMITライセンス下で公開される
- **コミュニティ駆動**: カスタム憲法、パターン、テーマがコミュニティによって貢献される
- **エンタープライズサポート**: 有料サポート層が大規模組織向けに提供される

### 5.3 規制上の制約

- **データプライバシー**: ユーザーコードはAIプラットフォームに送信されるため、プライバシーポリシーへの準拠が必要
- **セキュリティコンプライアンス**: エンタープライズユースケースではSOC 2/ISO 27001準拠が推奨

## 付録 A: EARSパターンクイックリファレンス

### イベント駆動(WHEN)

```
WHEN [イベント], the [システム] SHALL [応答]
```

**用途**: 特定のイベントやトリガーへの応答  
**例**: `WHEN ユーザーが保存をクリックする, the Form Service SHALL 検証を実行する`

### 状態駆動(WHILE)

```
WHILE [状態], the [システム] SHALL [応答]
```

**用途**: システム状態に依存する振る舞い  
**例**: `WHILE データ読み込み中である, the UI SHALL ローディングスピナーを表示する`

### 望ましくない振る舞い(IF...THEN)

```
IF [エラー条件], THEN the [システム] SHALL [応答]
```

**用途**: エラー処理と障害シナリオ  
**例**: `IF 検証が失敗する, THEN the Form Service SHALL エラーメッセージを表示する`

### オプション機能(WHERE)

```
WHERE [機能有効], the [システム] SHALL [応答]
```

**用途**: 条件付きまたは設定可能な機能  
**例**: `WHERE 自動保存が有効である, the Form Service SHALL 30秒ごとに保存する`

### 普遍的(SHALL)

```
The [システム] SHALL [応答]
```

**用途**: 常に有効な要件  
**例**: `The Form Service SHALL データをAES-256で暗号化する`
